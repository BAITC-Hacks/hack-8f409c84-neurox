# Необязательная интеграция OpenAI

В рабочем режиме ранжирование не обращается к сети. Для генерации векторов есть явный офлайн-подготовительный шаг: python -m scripts.build_embeddings --provider openai. Используется text-embedding-3-small; это соответствует [документации embeddings](https://developers.openai.com/api/docs/guides/embeddings).

LLM-провайдер отправляет один план для всей тройки через Chat Completions с JSON Schema, temperature=0 и seed=79; используемый по умолчанию gpt-4o-mini поддерживает [Structured Outputs](https://developers.openai.com/api/docs/guides/structured-outputs). seed сам по себе не гарантирует идентичность текста; стабильность обеспечивает кэш, а порядок подрядчиков всегда вычисляется локально.

Ключа нет в поставке. Живой API не проверялся. Перед отправкой данных внешнему API задайте LLM_PROVIDER=openai в локальном .env. Факты анонимизированного каталога попадут в этот запрос. Никакие ключи не выводятся в trace.

Провайдер использует ограниченный план вариантов вместо свободного сочинения: это не полноценный LLM-генератор прозы из расширенного промпта. После включения провайдера ранее закэшированные запросы продолжат отдавать сохранённый текст. Для измерения живого режима используйте python -m scripts.eval_explanations --live: он явно обходит кэш и сохраняет отдельный EVAL_LIVE.md.
